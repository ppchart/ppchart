# PPChart 用户投稿筛选设计

## 目标

在公共图库增加可直接选择的“用户投稿”入口，让审核通过的用户图表可以被单独发现和浏览。

## 交互

现有筛选行从“运行状态”改名为“内容范围”，保留并列的三个互斥选项：

- 可运行
- 不可运行
- 用户投稿

默认仍为“可运行”，不改变当前首页默认结果。

选择“用户投稿”时：

- 自动将图表类型重置为“全部”。
- 清空当前列表并从第一页加载用户投稿。
- 保留搜索词，允许在用户投稿范围内按标题搜索。
- 用户仍可继续切换回可运行或不可运行。

## 数据识别

仅展示审核通过并仍处于发布状态的用户投稿。

发布流程创建公共 `chart` 记录时使用既有 CID 协议：

```text
user-<userId>-<timestamp>-<random>
```

服务端使用 Prisma 条件：

```js
{ cid: { startsWith: "user-" } }
```

不新增数据库字段或迁移。管理员下架会删除公共 `chart` 记录，因此已下架投稿自然不会出现在筛选结果中。

## API

沿用 `GET /api/chart-list` 的 `runtime` 参数，增加：

```text
runtime=user
```

规则：

- `runtime=runnable`：维持现有可运行标签过滤。
- `runtime=unrunnable`：维持现有不可运行过滤。
- `runtime=user`：忽略运行标签，按用户 CID 前缀过滤。
- 用户投稿按 `createTime desc` 排序。
- 搜索、分页和总数统计继续复用现有逻辑。
- Redis 列表缓存键已经包含 `runtime`，无需修改键结构。

## 前端类型

`RuntimeFilter` 扩展为：

```ts
type RuntimeFilter = "runnable" | "unrunnable" | "user";
```

`runtimeFilters` 增加：

```ts
{ label: "用户投稿", value: "user" }
```

不新增页面或路由。

## 验收标准

- 首页出现“可运行 / 不可运行 / 用户投稿”三个并列选项。
- 默认仍选中“可运行”。
- 选择“用户投稿”后只返回 `user-*` 公共图表。
- 用户投稿按发布时间倒序。
- 搜索词可以与用户投稿筛选组合。
- 从具体图表类型切换到用户投稿时，类型自动重置为“全部”。
- 已下架投稿不会出现在用户投稿列表。
- 可运行、不可运行、分类和搜索功能不回归。
- 生产环境完成真实发布、筛选、下架后的列表验证。
